# Операторы поддержки в Telegram

Мост чата поддержки в служебную супергруппу с темами: одна тема на обращение.

| Что происходит | Где |
| --- | --- |
| Первое сообщение клиента | бот создаёт тему `#id · Имя` с шапкой и кнопками «Взять себе / Решено / Закрыть / Открыть снова» |
| Сообщения клиента, ответы и заметки из веб-панели, служебные строки | зеркалятся в тему |
| Оператор пишет в теме | уходит клиенту ответом; `//` в начале — заметка для коллег. Фото и картинки-файлы тоже уходят |
| Обращение закрыто / открыто снова | тема закрывается / открывается |
| Диалог удалён в панели | тема удаляется |

Писать клиенту из темы может только **платформенный админ с привязанным Telegram** (профиль → привязать Telegram).
Остальным бот отвечает в теме, что сообщение не отправлено.

## Настройка

1. Бот уже подключён (`TG_BOT_TOKEN`, `TG_BOT_NAME`).
2. Создать группу, в настройках включить **Темы** (группа станет супергруппой).
3. Добавить бота и сделать **администратором** с правом «Управление темами». Без админки бот не видит
   сообщения группы (режим приватности) и не может создавать темы.
4. Узнать id группы (вида `-1001234567890`): например, переслать сообщение из группы боту @getidsbot.
5. В `apps/server/.env`: `SUPPORT_TG_CHAT_ID=-100…`, перезапустить сервер.
   В логе (фильтр `🎧`): `Мост в Telegram включён, группа -100…`.

Пока мост включён, личные пуши операторам о новых обращениях в Telegram не дублируются — их заменяет тема.

## Как устроено

- `support-telegram.bridge.ts` подписан на `SupportEvents` (пакет `@app/support-chat-nest`) и отвечает через
  `SupportOperatorService` с каналом `TELEGRAM` — такие сообщения обратно в тему не зеркалятся.
- Апдейты групп модуль Telegram отдаёт в `AppTelegramAdapter.onGroupMessage / onGroupCallback` →
  `TelegramGroupRouter` (`src/messengers/adapters`) → мост.
- Связь диалог ↔ тема — таблица `SupportTelegramTopic`.
- Ограничение: один процесс на токен бота (long polling) — как и у всего модуля Telegram.
